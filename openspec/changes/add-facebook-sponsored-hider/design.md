# Design

Use an isolated content script with DOM-based detection, Chrome local storage, and popup messaging. No background worker or remote code is required.

Scrolling and slot collapse (0.1.4): read the current CometRelay environment during the wrapped feed component's render, using a hook resolved once and called consistently, to avoid relying only on observing RelayPublishQueue. Preserve configurable pre-existing module-loader accessors. Follow label IDs throughout inserted portal subtrees and deeper changed descendants. Allow a FeedUnit boundary containing one virtualized post. Collapse the single-child outer slot without changing site-owned styles or removing React nodes. Remember a confirmed ad while Facebook replaces its contents with an empty data-virtualized=true placeholder; reclassify material content when it returns, restoring slots for ordinary posts or disabled settings. Recheck material posts when scrolling brings them near the viewport and give unresolved content a fresh bounded wait when entering the viewport.

Feed restoration (0.1.3): add a small MAIN-world script that wraps only Facebook's module registration for CometFeedUnitErrorBoundary.react and RelayPublishQueue. Observe the queue's existing store and read the feed unit's sponsored_data.ad_id, independently implementing the signal found in the supplied ESUIT Ad Blocker. Add a neutral wrapper only for known ad or ordinary data; return unknown units unchanged. Preserve original calls, errors, return values and React hooks; do not rewrite module source or change network responses. Annotate rendered feed units with only ad/ordinary/unknown, never post content or IDs. Explicit null sponsorship releases ordinary posts even without a readable timestamp; an ad ID conceals the rendered unit through CSS before first paint. Missing or unsupported internals fall back to the existing DOM detector. Unknown DOM layouts have a bounded 1500 ms wait per content change, so normal posts cannot remain blank indefinitely. Late labels beyond this fallback can still flash; early data detection is best effort, not a universal timing guarantee. Keep Reels unchanged.

Timing: inject at document_start and observe the Document, which exists before documentElement. A CSS gate conceals unclassified containers before JavaScript or the mutation observer runs, including while preferences load. Each mutation batch is checked in a coalesced microtask. Supported sponsorship data or labels collapse the post; explicit ordinary data or recognizable timestamps release it. Unknown layouts receive a bounded 1500 ms wait, reset only for changed content or label identity. Recurring style changes and manual scans do not extend the deadline. Feed carousels and nested/excluded articles are exempt. Pending posts do not count as detected ads. Version information is exposed in the popup, DOM, and runtime status so stale tabs can be identified.

The detector recognizes exact English/Thai sponsored labels in visible post-header link metadata. It excludes author headings, post message content, comments, hidden text, and nested posts. A MutationObserver batches affected posts rather than rescanning the entire document on every change. Hiding uses an extension-owned attribute and stylesheet so disabling restores posts without replacing site-owned inline styles. Before checking a post, give it a temporary checking attribute synchronously to exempt it from the CSS gate while geometry and computed styles are read; finish classification before the browser paints. Recycled post containers are reclassified, and detached hidden nodes are pruned.

Current-layout support includes data-virtualized wrappers and aria-labelledby references to label text outside the post. Referenced text is used only when its owner is visible header metadata.

Sidebar detection finds an exact sponsored section heading and the smallest enclosing section containing a Facebook outbound ad link or sponsored-content menu. Traversal stops at adjoining headings or major page boundaries. Sidebar sections are rechecked in each batched scan, with previously hidden sections synchronously restored for classification.

Counts represent currently connected hidden post containers plus sponsored sidebar sections in the active document, not unique ads seen over time. Storage changes propagate to every open Facebook tab. Startup CSS temporarily conceals unchecked feed containers until stored preferences resolve. A stored disabled preference, or preference-loading failure, releases the gate. Users can independently disable label waiting to release unsupported posts while retaining ordinary ad detection.

Detection deliberately favors avoiding false positives. Facebook changes or more elaborate obfuscation may evade detection. Only controlled fixture behavior is a release claim until a signed-in Facebook session is tested.
